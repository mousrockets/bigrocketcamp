# Connexion communautaire Epic retirée

La version actuelle ne contacte plus OAuth Epic, AuthPlayer ou PsyNet pour lire des matchs ou des rangs. Le code de connexion, les constantes du client communautaire et le coffre de jetons ont été retirés. Les anciens endpoints HTTP et MCP restent compatibles avec les vieux onglets : les synchronisations renvoient `retired: true`, et les demandes d’autorisation renvoient HTTP 410. Cette interdiction est inconditionnelle, même si un ancien flag est remis à false ou une ancienne clé est réintroduite.

Les migrations 0006 et 0007 conservent les identifiants publics de jeu, leurs propriétaires, les dates de dernière réception et la couverture. Elles suppriment les copies de jetons et les autorisations device en attente. Elles préservent résultats, observations, exercices, réactions et dates des classements. Les derniers MMR sont marqués `frozen` : aucune actualisation distante du rang n’est promise. Les anciennes tables d’autorisation restent vides pour la compatibilité de schéma.

La clé d’exécution `EPIC_VAULT_KEY` doit être supprimée de Sites et la version redéployée pour appliquer la révision. Le flag `EPIC_COLLECTION_PAUSED=true` reste une protection pour un éventuel retour involontaire à une ancienne version ; il ne permet pas de réactiver le code actuel. La tâche de synchronisation horaire reste désactivée. Le récap à 8 h Europe/Paris continue uniquement à lire les données reçues ; les exécutions de tâches ne doivent ni changer ce choix, ni recréer des autorisations.

La suppression locale n’est pas une révocation côté Epic. Aucun logout global ni appel de révocation distant n’est effectué : le client OAuth communautaire n’était pas une application RL-Pompes distincte, et les effets sur une partie en cours ne sont pas garantis. Après fermeture du jeu, chaque joueur peut gérer ses accès dans les paramètres officiels Epic, onglet Applications, sans délier son compte PlayStation. Aucune invalidation de jeton distant n’est affirmée sans preuve.

Le remplacement est le Direct PC officiel, décrit dans `docs/direct.md`. Il utilise un socket local en lecture seule et une identité de jeu sans credential. Les anciens identifiants sont repris sans nouvelle connexion Epic. Un identifiant de console supplémentaire doit être confirmé par son propriétaire à partir d’un tableau reçu. Cette confirmation est déclarative, locale au club et réversible ; elle ne prouve pas un contrôle de compte auprès d’Epic et n’accorde aucun accès de connexion.
